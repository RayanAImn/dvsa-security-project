\section*{Project Context}

This report summarizes the DVSA vulnerability discovery and remediation project for the ICS-344 controlled university lab environment. DVSA was deployed in a non-production AWS account in \texttt{us-east-1}. All evidence and commands in this repository are intended for the course assignment only. Sensitive values such as JWTs, AWS account IDs, credentials, and private identifiers are redacted.

\section*{Architecture Summary}

The DVSA application uses a serverless AWS architecture:

\begin{itemize}
  \item Static frontend hosted on Amazon S3.
  \item Amazon API Gateway as the public API entry point.
  \item AWS Lambda functions for backend workflows.
  \item DynamoDB, S3, SQS, SES, CloudWatch, CloudTrail, and IAM for persistence, messaging, observability, and permissions.
\end{itemize}

\section*{Lesson 6: Denial of Service}

\subsection*{Goal and Root Cause}
The billing endpoint should process legitimate checkout requests without allowing duplicate or concurrent request bursts to exhaust Lambda/API Gateway capacity. The observed weakness was insufficient request protection for repeated billing attempts.

\subsection*{Evidence}
The repository includes PowerShell evidence for a controlled serialized request test and a controlled 10-job parallel request test. The parallel test produced mixed HTTP 200, 500, and 502 responses, which supports the availability impact claim. CloudWatch, Lambda metrics, and API Gateway throttling screenshots are stored under \texttt{screenshots/lesson-06/}.

\subsection*{Fix and Verification}
The remediation is API Gateway throttling plus backend idempotency/rate-control logic for billing. Post-fix verification should show excess requests rejected or throttled cleanly while normal checkout still works.

\section*{Lesson 7: Over-Privileged Function}

\subsection*{Goal and Root Cause}
The receipt email function should have only the permissions needed to send receipts and write logs. The observed weakness was broad execution-role permissions, especially around SES and representative wildcard service access.

\subsection*{Evidence}
Evidence includes the Lambda function page, execution role page, broad SES policy evidence, IAM Policy Simulator checks, post-fix simulator checks, and normal order workflow screenshots under \texttt{screenshots/lesson-07/}.

\subsection*{Fix and Verification}
The remediation replaces broad IAM permissions with a least-privilege policy. Verification uses IAM Policy Simulator denial results for unnecessary actions and confirms the normal order workflow still works.

\section*{Key Takeaways}

\begin{itemize}
  \item Serverless security depends on both code correctness and cloud-service configuration.
  \item Authentication and authorization must be enforced in backend logic, not only in the browser.
  \item IAM least privilege reduces blast radius when a function is abused.
  \item Availability controls such as throttling and idempotency are part of secure design.
  \item Error handling should protect users from internal details while preserving useful CloudWatch diagnostics.
\end{itemize}
